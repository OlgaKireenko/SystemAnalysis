# Итоговый проект

# 1. Контекст и границы задачи

## 1.1. Проблема

Клиенту необходимо получить микрозайм дистанционно, без посещения офиса организации.

Существующий процесс оформления займа должен позволять клиенту пройти необходимые проверки, передать заявку на рассмотрение и получить решение по заявке в цифровом виде.

Основная проблема, которую необходимо решить, — обеспечить понятный и управляемый процесс оформления микрозайма, в котором необходимые данные клиента последовательно проверяются, заявка передаётся во внешние системы, а результат проверки и решение по заявке корректно обрабатываются системой.

## 1.2. Цель разработки

Цель — реализовать функциональность онлайн-оформления микрозайма, которая позволит:

* выбрать предварительные условия займа;
* рассчитать предварительный график платежей;
* создать заявку на микрозайм;
* проверить необходимые данные клиента;
* получить информацию из БКИ;
* передать данные в СПР для принятия решения;
* обработать результат СПР;
* предоставить клиенту информацию о решении и условиях займа;
* при положительном решении перейти к оформлению займа.

## 1.4. Scope

В рассматриваемую функциональность входит процесс оформления микрозайма от расчёта условий до получения решения по заявке.

### В scope входят:

1. Выбор предварительных условий займа.
2. Расчёт предварительного графика платежей
3. Получение согласия клиента на обработку персональных данных.
4. Создание заявки на микрозайм.
5. Проверка возраста и гражданства клиента.
6. Запрос кредитной истории клиента в БКИ.
7. Передача заявки в СПР и обработка ответа СПР (интеграция с СПР)
8. Формирование статуса заявки.
9. Предоставление клиенту информации о результате.
10. Обработка подтверждения/отказа клиента от предложенных условий займа.
11. Передача заявки на дальнейшее оформление сделки при положительном решении.

--

## 1.5. Out of scope

В рамках данной функциональности не рассматриваются:

* регистрация и авторизация пользователя в мобильном приложении;
* разработка самого БКИ;
* разработка/текстирование СПР;
* внутренние алгоритмы скоринга СПР;
* формирование кредитной истории клиента в БКИ;
* страхование займа от невыплаты;
* страхование жизни заёмщика;
* взыскание задолженности;
* сопровождение займа после его выдачи;

Внешние системы рассматриваются только с точки зрения интеграции с ними и обработки их ответов.

# 1.6. Существенные неопределённости

На данном этапе исходной постановки недостаточно для полного проектирования функциональности.

Основные неопределённости:

* какие именно данные необходимо предоставить клиенту для создания заявки;
* какие поля являются обязательными;
* какие проверки выполняются до создания заявки, а какие после;
* какие именно данные передаются в БКИ;
* какие данные передаются в СПР;
* какие статусы может иметь заявка;
* какие причины отказа необходимо возвращать клиенту;
* сколько заявок может быть у одного клиента;
* как обрабатываются технические ошибки внешних систем;
* что происходит с заявкой при недоступности СПР;
* какие изменения заявки разрешены после её создания;
* на каком этапе клиент подтверждает условия займа;
* на каком этапе клиент может отказаться от кредита;
* что происходит после подтверждения условий.

* формат интеграции с БКИ;
* формат интеграции с СПР;
* правила обработки ошибок и таймаутов;
* правила повторных запросов;
* требования к производительности;
* требования к безопасности и хранению персональных данных;
* правила информирования клиента о результате.

# 1.9. Допущения

На текущем этапе принимаются следующие допущения:

1. Клиент уже зарегистрирован и авторизован в мобильном приложении.
2. БКИ и СПР доступны через API.
3. Кредитный конвейер является системой, управляющей процессом обработки заявки (оркестратор) 
4. Решение по заявке принимает СПР на основании переданных данных и результатов необходимых проверок.
5. Кредитная история запрашивается у БКИ до принятия окончательного решения.
6. При временной недоступности СПР система выполняет повторные попытки обращения.
7. Клиент получает информацию о результате рассмотрения заявки через мобильное приложение.
8. При положительном решении клиент должен подтвердить предложенные условия перед дальнейшим оформлением сделки.
9. Внешние системы самостоятельно отвечают за свою внутреннюю бизнес-логику; кредитный конвейер отвечает за корректное взаимодействие с ними и обработку результатов.

## 2.2 Функциональные требования: 

При получении от клиента данных, необходимых для оформления микрозайма, система должна создать заявку на получение микрозайма

До отправки формы на оформление займа система должна получить и зафиксировать согласие клиента на обработку персональных данных

При успешном создании заявки система должна проверить соответствие клиента установленным требованиям к возрасту и гражданству

После успешного прохождения проверки требований к возрасту и гражданству система должна получить кредитную историю клиента из БКИ, система успешно получает предусмотренный набор данных либо фиксирует предусмотренный сценарий невозможности их получения.

При получении всех данных, необходимых для принятия решения по заявке, система должна передать данные заявки и результаты выполненных проверок в СПР, в результате СПР получает полный набор данных для принятия решения по заявке.

При получении ответа от СПР система должна обработать результат решения по заявке, заявка получает результат автоматического решения и может перейти к оформлению займа или завершению процесса отказом.



## 2.3 Нефункциональные требования: 

1. Система должна сохранять работоспособность функции создания заявки при целевой одновременной нагрузке, значение которой необходимо определить у владельца системы. Допустимое время выполнения операции при такой нагрузке необходимо определить.

2. Сценарий получения и фиксации согласия клиента на обработку персональных данных должен успешно выполняться на всех поддерживаемых версиях iOS и Android; перечень версий остается открытым вопросом.

3. Система должна обеспечивать регистрацию факта отправки запроса в БКИ и связанных с ним событий обработки таким образом, чтобы по записи можно было установить факт и время запроса, идентификатор заявки и результат взаимодействия. Состав и срок хранения логов необходимо определить. (Аудируемость)

4. Система должна обработать полученный от СПР результат рассмотрения заявки в установленное время. Допустимое максимальное время обработки ответа необходимо определить с бизнес-заказчиком.
