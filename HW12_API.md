# 1. Сценарий и ресурсы API

## Пользовательский сценарий

Бизнес-пользователь банка работает с продуктовыми предложениями и использует продуктовый сервис для управления кредитными продуктами.

В рамках сценария пользователь может создавать кредитные продукты, просматривать существующие продукты, изменять их параметры, а также активировать и деактивировать продукты.

Каждое изменение кредитного продукта должно фиксироваться в истории изменений с указанием пользователя, даты и времени изменения.

## Ресурсы API

| Ресурс             | Назначение                                                                                                              | Source of Truth    |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `CreditProduct`    | Хранение и управление актуальной информацией о кредитном продукте и его текущем статусе                                 | Продуктовый сервис |
| `ProductChangeLog` | Хранение истории изменений кредитных продуктов с информацией о выполненных изменениях, пользователе и времени изменения | Продуктовый сервис |

# 4. Изменение ресурса

## Сценарий изменения

Бизнес-пользователь изменяет параметры существующего кредитного продукта, например, допустимый диапазоны суммы кредита, сроки или процентные ставки.

### API operation

**Method:** `PATCH`
**Path:** `/products/{productId}`

### Request

```json
{
  "loanAmounts": [
    {
      "min": 500000,
      "max": 1000000
    }
  ],
  "loanTerms": [
    {
      "min": 3,
      "max": 6,
      "interestRate": 21.9
    },
    {
      "min": 6,
      "max": 12,
      "interestRate": 20.9
    },
    {
      "min": 12,
      "max": 24,
      "interestRate": 19.9
    },
    {
      "min": 24,
      "max": 60,
      "interestRate": 18.9
    }
  ]
}
```

### Обоснование выбора PATCH

Используем `PATCH`, поскольку пользователь изменяет только отдельные параметры уже существующего кредитного продукта, а не заменяет весь ресурс целиком. `productId` передаётся в path и однозначно определяет изменяемый продукт. В request body передаются только те поля, которые необходимо изменить. `PUT` в данном случае менее удобен, поскольку предполагает полную замену ресурса. Отдельная command operation не требуется, так как изменение параметров является обычным частичным обновлением ресурса.

# Текстовый API-контракт

## Назначение операции

Изменение параметров существующего кредитного продукта.

## HTTP-метод и path

```text
PATCH /products/{productId}
```

## Path parameters

| Параметр    | Тип    | Обязательный | Ограничения              | Описание                           |
| ----------- | ------ | ------------ | ------------------------ | ---------------------------------- |
| `productId` | string | Да           | Уникальный идентификатор | Идентификатор изменяемого продукта |

## Headers

```text
Authorization: Bearer <token>
Content-Type: application/json
```

## Request body

| Поле                       | Тип           | Обязательное | Ограничения          | Описание                                   |
| -------------------------- | ------------- | ------------ | -------------------- | ------------------------------------------ |
| `loanAmount`               | array<object> | Нет          | Не менее 1 элемента  | Новый диапазон сумм кредита               |
| `loanAmount[].min`         | number        | Да           | > 0, `min < max`     | Минимальная сумма                          |
| `loanAmount[].max`         | number        | Да           | > `min`              | Максимальная сумма                         |
| `loanTerms`                | array<object> | Нет          | Не менее 1 элемента  | Новые диапазоны сроков и процентные ставки |
| `loanTerms[].min`          | number        | Да           | Целое число, > 0     | Минимальный срок в месяцах                 |
| `loanTerms[].max`          | number        | Да           | Целое число, > `min` | Максимальный срок в месяцах                |
| `loanTerms[].interestRate` | number        | Да           | > 0                  | Процентная ставка                          |

В `PATCH` все поля верхнего уровня request body являются необязательными, поскольку клиент может изменить только один параметр. Если передаётся `loanAmount` или `loanTerms`, обязательные поля соответствующих объектов должны быть заполнены.

## Успешный HTTP-status

```text
200 OK
```

## Response

```json
{
  "productId": "PL-001",
  "updatedAt": "2026-09-20T14:30:00Z"
}
```

## Response schema

| Поле        | Тип    | Обязательное | Ограничения              | Описание                           |
| ----------- | ------ | ------------ | ------------------------ | ---------------------------------- |
| `productId` | string | Да           | Уникальный идентификатор | Идентификатор изменённого продукта |
| `updatedAt` | string | Да           | ISO 8601                 | Дата и время последнего изменения  |
