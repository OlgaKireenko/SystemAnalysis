# Домашнее задание 15

## Постановка задачи на разработку

### 1. Название задачи

**Реализовать API для принятия решения клиентом по кредитным условиям**

---

### 2. Цель

Предоставить клиенту возможность после получения результата скоринга **согласиться или отказаться от предложенных кредитных условий**.

---

### 3. Контекст задачи

После прохождения скоринга клиенту доступны предложенные кредитные условия: сумма кредита, срок и процентная ставка.

Клиент должен выбрать одно из двух решений:

- согласиться с предложенными условиями;
- отказаться от предложенных условий.

Решение клиента необходимо сохранить в кредитной заявке и изменить её статус в соответствии с выбранным решением.

---

### 4. Ключевые источники

- результат скоринга;
- рассчитанные кредитные условия;
- данные кредитной заявки.

---

### 5. Заинтересованные лица

- клиент;
- кредитный конвейер;
- мобильное приложение.

---

### 6. Ограничения

- Решение можно принять только по существующей кредитной заявке в статусе "scoring_success"
- клиент должен принять/или отказаться от кредитных условий в течении 72 часов после успешного окончания скоринга, по истечении указанного срока заявка дожна быть закрыта кредитным конвейером (отдельная задача)
- По заявке должны быть сформированы кредитные условия.
- Расчёт кредитных условий и выполнение скоринга не входят в данную задачу.

---

### 7. Описание решения

Необходимо реализовать API для передачи решения клиента по предложенным кредитным условиям.

**Endpoint:**

`POST /v1/claims/isTermsAccepted`

#### Запрос при согласии клиента

``` json
{
"isTermsAccepted": true,
"claimId": "101"
}

{
  "isTermsAccepted": false,
  "claimId": "102"
} 

```


## Критерии приёмки

### Сценарий 1. Клиент согласен с кредитными условиями

**Предусловие:** кредитная заявка существует, заявке в статусе "scoring_success", по ней сформированы кредитные условия.

**Условие:** клиент отправляет запрос на `POST /v1/claims/isTermsAccepted` с параметрами:
`claimId = 101`, `isTermsAccepted = true`.

**Результат:** система фиксирует согласие клиента с предложенными кредитными условиями и успешно обрабатывает запрос.

---

### Сценарий 2. Клиент отказался от кредитных условий

**Предусловие:** кредитная заявка существует, заявка в статусе "scoring_success", по ней сформированы кредитные условия.

**Условие:** клиент отправляет запрос на `POST /v1/claims/isTermsAccepted` с параметрами:
`claimId = 101`, `isTermsAccepted = false`.

**Результат:** система фиксирует отказ клиента от предложенных кредитных условий и успешно обрабатывает запрос.

---

### Сценарий 3. Кредитная заявка не существует

**Предусловие:** кредитная заявка с указанным в параметрах `claimId` отсутствует.

**Условие:** клиент отправляет запрос на `POST /v1/claims/isTermsAccepted`.

**Результат:** система возвращает ошибку `404 Not Found`, решение клиента не сохраняется.

---

### Сценарий 4. Не передан идентификатор заявки

**Предусловие:** клиент сформировал запрос на передачу решения.

**Условие:** клиент отправляет запрос без параметра `claimId`.

**Результат:** система возвращает ошибку валидации `400 Bad Request`, решение клиента не сохраняется.


### Сценарий 5. Статус заявки !="scoring_success" 

**Предусловие:** клиент сформировал запрос на передачу решения.

**Условие:** клиент отправляет запрос по заявке, для которой статус !="scoring_success" 

**Результат:** система возвращает ошибку валидации `400 Bad Request`, решение клиента не сохраняется.

## Definition of Ready (DoR)

Задача считается готовой к передаче в разработку, если:

- **понятна цель задачи** — необходимо реализовать возможность передачи решения клиента по предложенным кредитным условиям;
- **определены границы задачи** — API принимает решение клиента и идентификатор кредитной заявки; расчёт кредитных условий и скоринг не входят в задачу;
- **понятны основные сценарии** — клиент может согласиться или отказаться от предложенных кредитных условий;
- **определены необходимые требования и ограничения** — параметр `isTermsAccepted` принимает только булевы значения `true` или `false`, а `claimId` является обязательным параметром;
- **определён API** — `POST /v1/claims/isTermsAccepted`;
- **определены формат запроса и параметры** — `claimId` и `isTermsAccepted`;
- **определены основные ошибки** — предусмотрена обработка несуществующей заявки и отсутствующих обязательных параметров;
- **задачу можно оценить** — понятно, какие изменения необходимо реализовать и какие сценарии протестировать;
- **команда понимает, что именно предстоит сделать** — реализовать API, обработать решение клиента и сохранить результат по кредитной заявке.

---

## Definition of Done (DoD)

Задача считается выполненной, если:

- реализован endpoint `POST /v1/claims/isTermsAccepted`;
- API принимает параметр `claimId`;
- API принимает параметр `isTermsAccepted`;
- при `isTermsAccepted = true` система фиксирует согласие клиента с кредитными условиями;
- при `isTermsAccepted = false` система фиксирует отказ клиента от кредитных условий;
- для несуществующей кредитной заявки возвращается ошибка `404 Not Found`;
- при отсутствии обязательного параметра возвращается ошибка `400 Bad Request`;
- реализованы и успешно проходят тесты для согласия и отказа клиента;
- реализованы тесты для основных негативных сценариев;
- API соответствует согласованной спецификации;
- код прошёл code review.
